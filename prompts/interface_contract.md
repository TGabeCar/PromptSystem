<instructions>
Define the interface contracts for this collaborative project. The goal is to enable independent, parallel development by clearly specifying:

1. **API Contracts** — Every endpoint or function that crosses a developer boundary
   - Exact URL paths, HTTP methods, request/response schemas with all field types
   - Or function signatures with full type annotations
   - Error response formats (consistent across all endpoints)
   - Authentication requirements per endpoint
   - Rate limits, pagination, and caching behavior

2. **Shared Data Models** — Models that multiple developers need to agree on
   - Complete type definitions with all fields, types, and validation rules
   - Serialization format (JSON schema, protobuf, etc.)
   - Which developer "owns" each model (responsible for schema changes)
   - Migration strategy when models change

3. **Integration Points** — Where components connect
   - Communication protocol (REST, gRPC, message queue, shared database, etc.)
   - Data flow direction
   - Failure handling at each boundary (what happens if the other side is down, slow, or returns errors?)
   - SLA at each boundary (expected response time, availability)

4. **Ownership Map** — Who is responsible for what
   - Clear file/directory ownership
   - Shared code that requires coordination to change
   - Review requirements for shared interfaces

5. **Change Management** — How to evolve interfaces safely
   - Interface versioning strategy
   - Breaking change process (notification, migration period, deprecation)
   - Backward compatibility requirements
   - How to test interface compliance
</instructions>
